SceneSolver

Multimodal forensic analysis system for surveillance video

SceneSolver ingests a surveillance clip and runs it through a staged pipeline: an autoencoder anomaly signal, a fine-tuned TimeSformer binary classifier, a multi-class incident classifier, conditional YOLOv8 weapon detection, audio-feature analysis, and a fusion/reasoning layer, with experimental reinforcement-learning and LLaVA narrative stages on top. A "normal" verdict at the binary stage suppresses the downstream classification and weapon stages, rather than letting a weak signal escalate on its own.

The system renders a structured PDF/HTML forensic report and can dispatch alerts to Telegram, Discord, and email. A Gradio application (Home / Analyse / Contact) backs the public demo; layered on top is "Sherl0ck," a voice-driven escalation agent that uses a Liquid Foundation Model for speech and Cohere for reasoning once a run crosses a critical threshold.

RAGnosis

Fork, extended into a deployed service

Biomedical retrieval-augmented chatbot

RAGnosis is a text-only biomedical retrieval-augmented chatbot. A Flask service retrieves related entities from a remote Neo4j Aura knowledge graph using keyword (Cypher CONTAINS) matching, then Cohere Chat generates a reply from that context. The production path - GET /, GET /health, POST /chat - runs as a Render web service under gunicorn.

The service is deliberately conservative: a failed retrieval returns a real configuration or connection error rather than an invented answer, and /health reports Neo4j and Cohere configuration status even when one is unavailable.

GraphOneSlice

Evidence-driven AI-ecosystem data pipeline

GraphOneSlice runs two ingestion workstreams. The original workstream is a deterministic research-paper pipeline: arXiv discovery, parsing, evidence-backed GitHub repository association, verification, validation, and PostgreSQL / Google Sheets export. The newer "AI Orbit" workstream ingests structured records - repositories, packages, models, companies, devices, and news - from verified sources such as the GitHub, PyPI, and npm APIs, official SDK type files, and several public catalogs, through Discovery → Extraction → Cleaning → Normalization → Entity Resolution → Classification → Relationship Mapping → Validation.

Source records are treated as authoritative and LLM output is not used as factual evidence; a missing fact is left null rather than inferred, and every entity and relationship carries a provenance record back to its source.

FaceID + Blockchain Verification

Tamper-evident identity-claim verification

A local pipeline that detects and encodes a face (dlib / face_recognition, a 128-dimensional encoding that is never uploaded or written on-chain), runs a live reverse-image search through Google Lens (via SerpAPI) or TinEye, and independently corroborates any social-media match with perceptual hashing computed locally rather than trusting the provider's label alone. The resulting evidence record is canonicalized and hashed with SHA-256, then anchored on the Ethereum Sepolia testnet through an immutable, append-only smart contract, so anyone can verify the record's integrity afterward with no API key and no private key.

The project states its scope precisely: it proves a record existed, unaltered, before a given block - it does not prove anyone's identity or social-account ownership.
